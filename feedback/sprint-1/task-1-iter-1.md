С normalize.css определись однозначно: либо добавь содержимое нормализации, либо не подключай пустой файл.

### БАГИ 🐞

Критические баги:

- По ТЗ компонент `SideBar` должен включать компонент `Statistic`. Сейчас `Statistic` создан, но нигде не используется, а `SideBar` напрямую рендерит `EmptyState`. Необходимо перенести содержимое статистики в `Statistic` и подключить его внутри `SideBar`.

Некритические баги:

- В `README.md` не указаны имя и ник участника. Информация по установке, запуску и сборке проекта добавлена правильно, но необходимо дописать недостающие данные.
- Компонент `TaskList` обёрнут в обычный ``<div>``. По ТЗ для списков необходимо использовать ``<ul>``, а элементы списка оформлять через ``<li>``. Пустое состояние также можно разместить внутри ``<li>``.
- `normalize.css` подключён в `global.css`, но сам файл полностью пустой. Необходимо либо добавить в него стили нормализации, либо удалить пустой файл и его импорт.
- В проекте остались неиспользуемые ресурсы стандартного шаблона и промежуточные файлы: `react.svg`, `vite.svg`, `hero.png`, `icons.svg`. Их лучше удалить, если они не нужны приложению.

### РЕКОМЕНДАЦИИ 💡

Рекомендую немного доработать архитектуру правой панели. Компонент `SideBar` должен отвечать за расположение панели, а содержимое статистики лучше оставить внутри отдельного компонента `Statistic`. Например:

```javascript
export function SideBar() {
  return (
    <aside className={styles.sideBar}>
      <Statistic />
    </aside>
  );
}
```

А уже внутри `Statistic` можно использовать универсальный `EmptyState`. Такой подход сохраняет структуру, указанную в ТЗ, и упрощает дальнейшее добавление реальной статистики. Подробнее о передаче данных между компонентами через props: [React — Passing Props to a Component](https://react.dev/learn/passing-props-to-a-component).

Для `TaskList` лучше сразу сохранить семантику настоящего списка:

```javascript
<ul className={styles.taskList}>
  <li className={styles.emptyItem}>
    <EmptyState />
  </li>
</ul>
```

В следующих заданиях внутри этого компонента появятся задачи, поэтому правильная структура ``<ul>`` и ``<li>`` позволит не переделывать разметку позже и сделает её понятнее для вспомогательных технологий. Подробнее: [MDN — элемент ul](https://developer.mozilla.org/ru/docs/Web/HTML/Reference/Elements/ul).

В `README.md` стоит добавить имя и ник участника, а заголовок `React + Vite` заменить на `Taskana App`. Так файл будет полностью соответствовать ТЗ и сразу даст понять, какому проекту он принадлежит.

Пустой `normalize.css` лучше не оставлять подключённым. Можно добавить готовую нормализацию стилей из официального репозитория [normalize.css](https://github.com/necolas/normalize.css) либо удалить файл и его импорт, если необходимый сброс уже выполнен в `global.css`.

Перед отправкой работы полезно очищать папку `public` от неиспользуемых файлов шаблона Vite и запускать:

```javascript
npm run lint
npm run build
```

В целом проект уже хорошо организован, а перечисленные изменения небольшие и сделают структуру полностью соответствующей ТЗ. 👍
